# 1. 요약

## **01. 공용 Grid를 행 가상화 한 갈래로 통일했다**

autoHeight 그리드가 행을 전부 DOM에 그려, 세대관리 4,997행 단지는 API 응답 후 첫 행까지 38.7초, 가장 긴 메인 스레드 멈춤이 38.6초였다. 페이지를 유일한 스크롤러로 두고 보이는 행만 그리게 바꾸자 첫 행 0.10초, 멈춤 0.21초, DOM에 그린 행은 5,067개에서 16개가 됐다(#2487). 이어서 호출부가 고르던 `domLayout`을 공용 `Grid`에서 없애 110파일에 걸쳐 모든 그리드를 같은 스크롤 구조로 옮겼다(#2506).

## **02. 스크롤바를 레이아웃 폭에서 빼고 hd-ds 컴포넌트로 만들었다**

저해상도 윈도우 PC에서 네이티브 스크롤바가 사이드 네비와 본문 폭을 깎고 있었다. CSS로는 폭을 차지하지 않는 스크롤바를 만들 수 없어 hd-ds에 OverlayScrollbars 기반 `Scrollbar`·`useScrollbar`를 추가하고(hd-ds#140 +709) 앱 셸, AG Grid, Table, 사이드 네비에 붙였다(#2507 +1,153/−769). 같은 막대를 sticky로 바꿔 표 가로 스크롤바를 페이지네이션 위에 띄우는 데(#2526)도 재사용했다.

## **03. 사업장 정보에 업체·개인 구분과 구분별 필수값을 넣었다**

업체 기준 단일 양식이라 개인 사업장에도 사업자 번호가 보이고 상호명 외에는 모두 선택값이던 세대관리 상세 사업장 정보에 구분 라디오와 조건부 필수를 넣었다(#2432 +1,005/−140 · 18파일). 리뷰 3라운드에서 숨김 필드 비우기와 주민등록번호 형식 검증을 보강했고, 서버가 숫자 13자리로 돌려주는 주민등록번호를 화면 형식과 맞추는 후속 수정(#2480)까지 이어졌다.

## **04. PR CI에 부문 게이트를 붙이고 리뷰 요청을 작성자 파트로 좁혔다**

PR CI가 설치와 빌드만 돌려 타입 오류, 테스트 실패, 브랜치·커밋 규칙 위반이 리뷰 전에 드러나지 않았다. it-ci-gates의 typescript·conventions 게이트와 commitlint를 붙였고(#2478), 게이트가 UTC 러너에서 결재 매핑 테스트 6건 실패를 드러내 vitest 시간대를 고정했다(#2482). 리뷰 요청은 CODEOWNERS 경로 분할(#2407)로 좁혔다가 요청이 오히려 늘어 작성자 소속 파트 기준(#2424)으로 다시 바꿨다.

## Challenge 01 : 전부 그리던 그리드를 보이는 행만 그리게 하고 레이아웃 선택을 없앴다

`그리드 · 렌더링 성능 · 리팩토링`

| 항목 | 값 |
| --- | --- |
| 티켓 | HDIT-4031 (개발완료) · HDIT-4132 (개발완료) |
| 실적 | 12.2h + 2.1h (업무 로그 기준 — 5절 참고) |
| PR | #2487 · +1,076/−64 · 9파일, #2506 · +338/−314 · 110파일 |
| 산출 | `use-virtual-auto-height` · `revealGridVirtualRow` · `BaseModal scrollBody` · Notion 설계 문서 |

**상황**
autoHeight 그리드는 행을 전부 DOM에 그린다. 세대관리 세대주 탭에서 4,997행 단지를 열면 API 응답 후 첫 행까지 38.7초가 걸렸고 그동안 메인 스레드가 38.6초 멈췄다. 고정 높이 그리드는 반대로 안쪽 스크롤이 남아 모달·패널·1,000행 넘는 세대차량에서 이중 스크롤이 생겼다.

**어려웠던 지점**

1. **페이지와 그리드 안쪽 중 누가 스크롤 기준인지가 입력 경로마다 갈렸다.** 그리드를 sticky 상자에 넣고 바깥 spacer로 전체 높이를 잡은 뒤, 페이지 스크롤을 그리드 안쪽 `scrollTop`에 맞추고 키보드 이동처럼 그리드가 스스로 스크롤하면 페이지가 따라가게 했다. 휠·터치·포인터 입력은 되밀지 않고, 페이지가 더 움직이지 못하면 보정을 멈추는 조건까지 넣어야 키보드 ↑·PageUp·↓에서 포커스 셀이 가려지는 횟수가 0이 됐다.
2. **화면 밖 행을 다루던 기존 경로가 그 행이 DOM에 없다는 전제를 몰랐다.** 오류 셀 이동, GridField 행 추가, 동호 설정 행 추가가 모두 화면 밖 행을 찾았다. `revealGridVirtualRow`로 그 행을 먼저 그리게 했고, 세대 상세 슬라이드 상자의 `overflow: hidden`은 스크롤 컨테이너를 만들어 sticky가 페이지를 따라가지 못해 `overflowX: clip`으로 바꿨다.
3. **가상화를 autoHeight에만 넣으면 그리드가 두 갈래로 남는다.** 호출부가 `domLayout`을 고르는 한 고정 높이 그리드의 이중 스크롤은 그대로였다. `GridProps`에서 `domLayout`을 지워 넘기면 타입 오류가 나게 하고, 모달 안에서는 그리드 헤더가 페이지 헤더 높이(114px)만큼 내려와 붙는 문제를 `.MuiModal-root`의 sticky 기준 변수를 0으로 재설정해 막았다.

**판단**
그리드를 레이아웃 옵션으로 고르게 두는 대신 공용 `Grid`가 레이아웃을 직접 정하게 했다. 예외는 오른쪽 폼과 높이를 맞춰야 하는 연말정산 직원 목록 하나로, 새 prop `fixedHeight`로만 열었다. 그 대가로 인쇄(`window.print`) 시 화면에 그려진 행만 인쇄될 수 있는 제한과, `theme.ts`의 변수 재설정이 모든 모달·드로어의 `StickyTable`·`StickyReveal` 기준까지 0으로 바꾼다는 영향을 PR에 명시하고 받아들였다.

**남은 것**
공용 `Grid`를 쓰는 화면은 레이아웃을 고르지 않아도 행 가상화로 그려진다. 렌더링 속도를 같은 단지, 같은 탭, 같은 커밋 기준으로 재는 표(첫 행 시각 · 최장 멈춤 · DOM 행 수)가 PR 본문에 남아 다음 비교의 기준이 된다.

## Challenge 02 : 폭을 차지하던 네이티브 스크롤바를 hd-ds 오버레이로 바꿨다

`디자인 시스템 · 스크롤 UX`

| 항목 | 값 |
| --- | --- |
| 티켓 | HDIT-3443 (개발완료) · HDIT-4400 (개발완료) · HDIT-4401 (개발완료) |
| 실적 | 4.3h + 1.0h + 1.0h |
| PR | hd-ds#140 · +709/−1 · 8파일, #2507 · +1,153/−769 · 20파일, #2526 · +102/−13 · 7파일, #2525 · +334/−50 · 3파일 |
| 산출 | hd-ds `Scrollbar` · `useScrollbar`, `useGridScrollbar`, `getStickyHScrollbarSlotSx` |

**상황**
해상도가 낮은 윈도우 PC에서 네이티브 스크롤바가 두껍게 그려지고, 그 폭만큼 사이드 네비와 본문 영역이 좁아진다. 표 가로 스크롤바는 표 맨 아래에만 붙어 sticky 페이지네이션에 가려지고, 행이 많으면 페이지를 끝까지 내려야 가로로 움직일 수 있다(HC-2993 요청).

**어려웠던 지점**

1. **CSS만으로는 Modulor Scrollbar 스펙을 맞출 수 없었다.** `::-webkit-scrollbar`와 `scrollbar-width`는 둘 다 폭을 차지하고, thumb 페이드와 트랙 클릭 이동도 표현하지 못한다. 그래서 라이브러리를 들이되, 라이브러리 기본 구조(자식을 새 viewport로 옮김)는 React 자식과 AG Grid 내부 DOM을 깨뜨려 배제하고 기존 스크롤 요소를 그대로 viewport로 쓰는 `useScrollbar`를 만들었다.
2. **스크롤바를 대상 요소 안에 붙이면 휠 스크롤 중에 바가 흔들렸다.** 브라우저가 스크롤을 컴포지터에서 먼저 처리한 뒤 라이브러리가 JS `transform`으로 바를 되돌리느라 한 프레임씩 늦었다. 스크롤되지 않는 부모(`scrollbars.slot`)에 붙이자 보정이 사라지고 thumb가 `ScrollTimeline`으로 컴포지터에서 함께 움직였다. 흔들림 비교는 태스크 스페이스가 화면을 그리지 않아 사용자가 Orca 탭에서 직접 확인했다.
3. **빌드한 `ds.css`에서 라이브러리 기본 변수가 테마를 이겼다.** 라이브러리 CSS가 테마보다 뒤에 오고 `.os-scrollbar`에 `--os-size: 0`을 둔다. Storybook 개발 서버는 로드 순서가 반대라 드러나지 않아, 스토리마다 라이브러리 CSS를 문서 끝에 다시 넣어 빌드 순서를 재현한 뒤 측정했다.

**판단**
`useScrollbar`의 `container`를 선택값으로 두고 생략하면 흔들릴 수 있다고 TSDoc에 적는 쪽을 택했다 — 감싸는 부모를 강제하면 기존 화면마다 DOM을 바꿔야 했다. AG Grid는 `scrollbarWidth: 0`을 공용 기본값으로 두어 윈도우에서 세로 스크롤바 자리로 비워 두던 16px 여백을 없앴다. 표 가로 스크롤은 프록시 스크롤바를 새로 두고 `scrollLeft`를 동기화하는 대신 같은 오버레이 막대를 `position: sticky`로 바꿔 스크롤 경로를 하나로 유지했고, sticky 옵션을 hd-ds에 올리는 일은 사용처가 이 저장소뿐이라 미뤘다.

**남은 것**
새 스크롤 영역은 `Scrollbar`, 기존 요소와 서드파티 viewport는 `useScrollbar`로 붙이는 두 경로가 hd-ds에 생겼고, 두 번째 사용처(#2526)가 이미 같은 막대를 재사용한다. 실제 윈도우 저해상도 환경과 실제 페이드 경과 시간은 확인하지 못한 채로 남았다.

## Challenge 03 : 업체·개인 구분을 넣고 화면에 없는 값이 저장을 막지 않게 했다

`세대관리 · 폼 검증`

| 항목 | 값 |
| --- | --- |
| 티켓 | HDIT-3434 (개발완료) · HDIT-4230 (개발완료) |
| 실적 | 2.1h + 1.0h |
| PR | #2432 · +1,005/−140 · 18파일, #2480 · +218/−18 · 11파일 |
| 산출 | `clearHiddenBizFields` · `shared/lib/resident-registration-no`의 `formatStoredResidentRegistrationNo` |

**상황**
세대관리 상세의 사업장 정보가 업체 기준 단일 양식이라 개인 사업장에도 사업자 번호가 노출되고 상호명과 대표자를 중복 입력해야 했다. 상호명 외에는 모두 선택값이라 일부만 입력된 사업장 정보가 그대로 저장됐다.

**어려웠던 지점**

1. **개인으로 바꿨을 때 숨긴 칸의 값을 남길지 비울지가 갈렸다.** 남기면 화면에 없는 값이 형식 검증으로 저장을 막거나 개인 사업장에 사업자 번호가 전송된다. 비우면 업체로 돌아올 때 두 칸이 비어 있다. 비우는 쪽을 택하되 업체 상호명은 보존했고, 리뷰 2라운드에서 서버에서 불러온 개인 사업장에 이미 들어 있던 사업자 번호도 남는 경로라는 것을 찾아 저장 변환과 불러오기가 같은 `clearHiddenBizFields`를 쓰게 모았다.
2. **주민등록번호 형식 규칙이 없다고 판단했다가 정정했다.** 리뷰 지적에 「PRD에 형식 규칙이 없어 기획 결정이 필요하다」고 답했는데, 직원 기본정보에 이미 `/^\d{6}-\d{7}$/` 규칙과 하이픈 자동 입력이 있었다. 정정 코멘트를 남기고 규칙을 `shared/lib`로 옮겨 세대관리와 직원이 함께 쓰게 했다. 엑셀 업로드가 함께 쓰는 `bizRegistrationSchema`에는 넣지 않아 하이픈 없는 업로드 값이 새로 막히지 않게 했다.
3. **화면 규칙과 서버 저장 형식이 어긋나 재저장이 막혔다.** 서버(HDIT-3433)는 숫자 13자리로 돌려주는데 화면은 `6자리-7자리`만 통과시켜, 다른 항목만 고쳐도 형식 오류로 저장되지 않았다(HDIT-4230). 백엔드와 「DB에는 하이픈 없이 저장」으로 합의하고, 표시할 때 하이픈을 붙이고 전송할 때 빼는 인사관리 방식에 맞췄다.

**판단**
숫자 13자리만 검사하는 방식은 인사관리와 입력 동작이 갈려 배제했고, 표시와 전송을 나누는 변환을 공용 함수 하나로 묶었다. 그 대가로 숫자 13자리가 아닌 예전 저장값은 표시 변환 없이 그대로 보여 형식 오류가 날 수 있고, 다시 입력해야 저장된다는 점을 PR의 Risks에 남겼다. 기존 저장 데이터도 자동 보정 없이 같은 검증을 적용하기로 했다.

**남은 것**
주민등록번호의 표시 형식과 저장 형식을 가르는 변환이 `shared/lib/resident-registration-no` 한 곳에 있고 세대관리와 직원 기본정보가 함께 쓴다. 사업장 섹션을 그리지 않는 아파트 단지에서 숨은 사업장 값이 저장을 막는 결함은 다음 스프린트 HDIT-4843(#2556)으로 이어졌다.

## Challenge 04 : 리뷰 전에 드러나야 할 실패를 PR 게이트로 당기고 리뷰 요청 대상을 다시 정했다

`CI/CD · 개발 프로세스`

| 항목 | 값 |
| --- | --- |
| 티켓 | HDIT-4173 (개발완료) · HDIT-3918 (개발완료, reopen 1회) · HDIT-4231 (개발완료) |
| 실적 | 2.6h + 1.0h + 1.0h |
| PR | #2478 · +561/−68 · 12파일, #2407 · +101/−7 · 3파일, #2424 · +86/−91 · 5파일, #2482 · +143/−392 · 5파일 |
| 산출 | `ci-gate.yml` · commitlint 훅 · `.github/part-members.json` · vitest `TZ` 고정 |

**상황**
PR CI(`pr-build`)는 설치와 빌드만 돌려 린트, 타입체크, 테스트 실패와 런북 규칙(브랜치명, 커밋 메시지, PR 본문) 위반이 리뷰 전에 드러나지 않는다. CODEOWNERS가 `*` 한 줄이라 변경 범위와 관계없이 FE 3명 전원이 리뷰어로 요청돼 `user-review-requested:@me`로 내 담당 PR만 걸러 볼 수 없다.

**어려웠던 지점**

1. **게이트 기본값이 이 저장소에서는 아무것도 검사하지 않았다.** 루트 `tsconfig.json`이 references만 있어 기본 `tsc --noEmit`은 0개 파일을 검사하고, `test` 스크립트는 감시 모드였다. `tsc -b`와 `vitest run`으로 지정했고, 호출된 게이트가 권한을 `contents: read`로 낮춰 `GITHUB_TOKEN`으로는 hd-ds 설치가 403이 나서 `PACKAGES_READ_TOKEN` 시크릿을 썼다. 게이트에 `packages: read`를 더하는 쪽은 기존 소비 저장소가 깨져 배제했다.
2. **게이트를 켜자 로컬에서 통과하던 테스트가 실패했다.** 결재 상세 매핑 테스트 6건이 UTC 러너에서 `draftedAt`이 9시간 어긋났고(HDIT-4231), Grid 방향키 선택 테스트는 키 입력 뒤 한 틱만 기다려 간헐적으로 실패했다. 테스트마다 기대값을 고치는 대신 `test.env`에 `TZ: 'Asia/Seoul'`을 두었는데, 그러려면 vite 7 설정에 `test` 키를 넣을 수 있게 vitest를 2에서 4로 올려야 했다. gate 1회는 약 15분 30초, 그중 test가 9분 24초였다.
3. **리뷰 요청을 경로로 좁히자 요청이 오히려 늘었다.** #2407은 파트별 경로 58줄로 CODEOWNERS를 나눴지만, 변경 경로마다 해당 파트 담당자와 공통 오너가 함께 요청되면서 요청이 너무 많이 들어왔다. 티켓이 reopen돼 #2424에서 CODEOWNERS를 지우고 작성자가 속한 파트와 프론트 그룹에게만 요청하는 방식으로 바꿨다.

**판단**
리뷰 요청과 Slack 알림을 변경 경로가 아니라 작성자 소속 파트로 정했다. 대가로 명단(`part-members.json`)에 없는 작성자(신규 입사자, 봇)의 PR에는 자동 리뷰 요청도 알림도 가지 않고, 머지 전에 develop에서 딴 브랜치는 명단 파일이 없어 404로 실패한다 — 리뷰어가 「알고 넘어가는 것으로」 승인했다. CI 게이트는 `edited`에도 반응해 같은 커밋으로 여러 번 돌던 것을 PR 단위 `concurrency`로 묶되, 실행 중 취소하면 중앙 `verdict`가 실패를 남겨 `cancel-in-progress: false`로 대기 중인 실행만 교체했다.

**남은 것**
타입 오류, 테스트 실패, 브랜치·커밋·PR 본문 규칙 위반이 리뷰 전에 PR 체크로 드러나고, 커밋 시점에도 같은 commitlint 규칙이 돈다. 같은 구성을 hd-cloud-admin에 옮긴 작업(HDIT-4268, admin#170)은 다음 스프린트 티켓이다. ruleset에 `verdict` 필수 검사를 등록하는 일은 후속으로 남았다.
