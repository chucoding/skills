Notion 페이지 URL이나 UUID가 주어지거나 Notion 문서를 읽고 쓰라는 요청이 있을 때 이 스킬을 적용한다. 수정 전 조회와 최소 범위 수정, Notion 마크다운 규격(`notion://docs/notion-flavored-markdown-spec`) 확인은 Notion MCP 도구 설명을 따르고, 이 스킬은 그 위에 더하는 작성 규칙과 조회나 수정이 실패했을 때의 점검표를 다룬다.

### 1. Notion용 마크다운

- 테이블은 Notion에서 지원되는 테이블 문법을 사용하고, 셀 안에는 서식 있는 텍스트만 사용한다.
- 특수문자(역슬래시, 별표, 물결표, 백틱, 달러, 대괄호, 꺾쇠괄호, 중괄호, 파이프, 캐럿)는 문맥에 따라 이스케이프한다. 코드 블록 안은 리터럴로 둔다.
- 구분선(`---`)은 새로 만들지 않는다. 섹션은 `#` 제목으로만 나누고, 목록이나 테이블로 구조를 정리한다.
- 기존 페이지에 있는 구분선은 수정 요청 범위에 들어오지 않으면 그대로 둔다.

### 2. 작성 형식

- Notion 페이지에 쓰는 내용은 한국어로 작성한다.
- 섹션은 `#` 제목으로 구분하고, 비교나 정리에는 테이블을 사용한다.
- 예시 코드는 언어 태그를 포함한 코드 블록으로 작성한다.
- 설계 문서, 아키텍처 설명, 데이터 흐름 등을 정리할 때 Mermaid 다이어그램을 적극 활용한다.
  - 컴포넌트/모듈 간 의존 관계
  - 데이터 흐름(API 호출, 번들 분리 등)
  - 시퀀스 다이어그램(사용자 플로우)
  - 아키텍처 결정 비교

### 3. 문제 파악 점검표

| 증상 | 확인 사항 |
|------|-----------|
| 조회 시 오류 또는 빈 결과 | 1) URL 또는 페이지 식별자가 정확한지 2) Notion 연동 계정이 해당 페이지에 접근 가능한지 3) Notion MCP 또는 앱 연결을 사용할 수 있는지. 접근 문제로 보이면 사용자에게 Notion URL 확인과 공유 설정(연동 계정 접근 허용)을 안내 |
| 수정 시 오류 | 1) 페이지 식별자가 조회 결과와 일치하는지 2) 선택 문맥이 본문에서 유일하게 일치하는지 3) 새 내용이 Notion 마크다운 규격에 맞는지 |
| 테이블 또는 서식 깨짐 | Notion 마크다운 규격에서 테이블과 목록 문법을 재확인하고, 필요한 특수문자를 이스케이프했는지 확인 |
