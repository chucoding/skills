Notion 마크다운 규격(테이블 문법, 특수문자 이스케이프, 구분선 금지), 한국어 작성과 Mermaid 다이어그램 활용, 스펙 문서의 구성도와 전체 흐름 섹션 구성, 외부 서비스와 인프라를 아이콘으로 보여야 하는 시스템 구성도만 drawio XML에 아이콘 셰이프를 넣어 그려 PNG로 업로드하는 절차, 세션 작업을 노션에 쓸 때 사용자 질문과 결정을 순서대로 남기는 결정내역 섹션, 댓글 수정에 Business 플랜이 필요할 때의 정정 답글 절차, MCP 인증이 끊겼을 때 로그인 창을 띄우는 재연결 절차, 접근 실패 시 공유 설정 안내를 포함한다. Notion 링크나 페이지 UUID가 주어지거나 Notion 문서를 읽고 쓰라는 요청이 있을 때 사용한다.
---

Notion 페이지 URL이나 UUID가 주어지거나 Notion 문서를 읽고 쓰라는 요청이 있을 때 이 스킬을 적용한다. 수정 전 조회와 최소 범위 수정, Notion 마크다운 규격(`notion://docs/notion-flavored-markdown-spec`) 확인은 Notion MCP 도구 설명을 따르고, 이 스킬은 그 위에 더하는 작성 규칙과 연결, 접근 실패 처리만 다룬다.

### 1. Notion용 마크다운

- 테이블은 Notion에서 지원되는 테이블 문법을 사용하고, 셀 안에는 서식 있는 텍스트만 사용한다.
- 특수문자(역슬래시, 별표, 물결표, 백틱, 달러, 대괄호, 꺾쇠괄호, 중괄호, 파이프, 캐럿)는 문맥에 따라 이스케이프한다. 코드 블록 안은 리터럴로 둔다.
- 구분선(`---`)은 새로 만들지 않는다. 섹션은 `#` 제목으로만 나누고, 목록이나 테이블로 구조를 정리한다.
- 기존 페이지에 있는 구분선은 수정 요청 범위에 들어오지 않으면 그대로 둔다.

### 2. 작성 형식

- Notion 페이지에 쓰는 내용은 한국어로 작성한다.
- 섹션은 `#` 제목으로 구분하고, 비교나 정리에는 테이블을 사용한다.
- 예시 코드는 언어 태그를 포함한 코드 블록으로 작성한다.
- 다이어그램 도구는 그림의 종류를 먼저 보고, 시스템 구성도일 때만 아이콘을 쓸 요소가 있는지 본다.
  - 처리 흐름과 동작, 코드 내부 구조를 그리는 그림은 Mermaid로 노션 본문에 바로 넣는다. 흐름 그림은 외부 서비스가 나와도 Mermaid로 그리고, 구조 그림에 실행 환경이나 외부 서비스가 함께 나오면 아래 시스템 구성도 기준으로 고른다.
    - 데이터 흐름(API 호출, 번들 분리 등)
    - 시퀀스 다이어그램(사용자 플로우)
    - 상태 다이어그램
    - 코드 안 모듈과 컴포넌트 간 의존 관계
    - 아키텍처 결정 비교
  - 시스템을 이루는 실행 환경과 외부 서비스를 그리는 시스템 구성도는 아이콘으로 정체를 보여 줄 외부 서비스나 인프라가 있는지로 고른다.
    - Slack, GitHub, AWS, PostgreSQL처럼 아이콘을 쓸 요소가 하나 이상이면 `drawio`로 그려 PNG 이미지로 넣는다.
    - 아이콘으로 표현할 요소가 하나도 없으면 drawio를 쓰지 않고 Mermaid로 그린다. Mermaid를 drawio로 변환한 그림은 네모 상자뿐이라 Mermaid와 다를 것이 없기 때문이다.
- 사용자가 "스펙 문서 작성해줘"처럼 설계나 구축 결과를 정리하는 스펙 문서를 요청하면 개요 바로 뒤에 다이어그램 섹션 두 개를 이 순서로 둔다. 개요가 없으면 페이지 맨 앞에 두고, 그릴 대상이 없는 섹션은 만들지 않는다. 스펙 문서가 아닌 노션 작성에서는 이 구성을 강제하지 않고 위 기준만 따른다.
  1. `# 구성도`: 시스템을 이루는 실행 환경과 외부 서비스(GitHub, Slack, AWS, DB 등)를 그린 시스템 구성도다. 위 기준대로 아이콘으로 보일 요소가 있으면 drawio, 없으면 Mermaid로 그린다.
  2. `# 전체 흐름`: 처리 흐름이나 시퀀스를 Mermaid로 그린다.
- drawio로 그릴 때 순서는 다음과 같다.
  1. `Skill` 도구로 `drawio` 스킬을 호출한다. 그 스킬은 Mermaid 작성을 우선 권하지만 이 경우에는 따르지 않고 draw.io XML을 직접 작성한다. 좌표는 손으로 맞추지 않고 `--layout horizontalFlow`로 배치한다. 단계가 위에서 아래로 이어지는 그림이면 `verticalFlow`를 쓴다.
  2. 그림에 나오는 외부 서비스와 인프라마다 아이콘 셰이프를 쓴다. 스타일 이름은 추측하지 않고 아래 순서로 찾은 값을 그대로 쓴다.
     - 내장 셰이프 라이브러리: draw.io 공식 셰이프 색인(`https://raw.githubusercontent.com/jgraph/drawio-mcp/main/shape-search/search-index.json`)을 받아 `title`과 `tags`로 찾고, 그 항목의 `style`을 그대로 쓴다. AWS(`mxgraph.aws4.*`), Azure, GCP, Kubernetes와 일부 웹 로고(`mxgraph.weblogos.github` 등)가 여기에 있다.
     - 색인에 없는 브랜드 로고(Slack 등): draw.io 아이콘 서비스를 `curl 'https://icons.diagrams.net/api/icons/search?q=<서비스 이름>&p=0&c=5'`로 검색해 결과 중 제목이 서비스 이름과 맞는 로고의 `url`을 고르고, 스타일 `shape=image;html=1;verticalAlign=top;verticalLabelPosition=bottom;labelBackgroundColor=default;imageAspect=0;aspect=fixed;image=<url>`로 넣는다. 이 이미지는 원격 URL이라 내보낼 때 네트워크가 필요하고, PNG에 포함된 XML도 그 URL을 가리킨다.
     - 두 곳 모두에서 맞는 결과가 없는 요소만 일반 도형으로 그린다. 색인 다운로드나 검색 요청 자체가 실패한 것은 결과가 없는 것과 다르므로 6단계로 간다.
     - 찾고 나니 아이콘을 쓴 요소가 하나도 없으면 drawio를 그만두고 Mermaid로 그린다.
  3. `drawio` 스킬의 내보내기 절차대로 XML을 포함한 PNG(`<이름>.drawio.png`)로 내보낸다. 내보낸 PNG는 draw.io에서 다시 열어 고칠 수 있다. 내보낸 PNG를 `Read`로 열어 아이콘으로 넣은 요소가 모두 그려졌는지 확인하고, 하나라도 빠졌으면 6단계로 간다.
  4. `notion-create-file-upload`에 파일 이름을 넘겨 업로드 URL을 받고, Bash의 `curl`로 받은 `upload_headers`를 모두 붙여 `file` 필드에 PNG를 담은 multipart POST 요청을 한 번 보낸다. 한 번에 올릴 수 있는 파일은 20 MiB까지다.
  5. 응답의 `suggested_markdown`을 새 페이지면 `notion-create-pages`의 본문에, 기존 페이지면 `notion-update-page`로 원하는 위치에 넣는다. 업로드한 파일은 페이지에 넣기 전까지 임시 상태라 만료되면 지워지므로 바로 넣는다.
  6. draw.io 데스크톱 CLI가 없어 PNG를 만들지 못했거나, 셰이프 색인 다운로드나 아이콘 검색이 실패했거나, 아이콘이 하나라도 그려지지 않았거나, 파일이 20 MiB를 넘거나, 업로드가 실패하면 받은 오류를 그대로 보여주고 Mermaid로 대신 그릴지 사용자에게 묻는다.
- 이번 세션에서 한 작업을 노션에 작성하라는 요청을 받으면 페이지 맨 끝에 `## 결정내역` 섹션을 하나 넣는다. 사용자가 나중에 자기 결정을 다시 검토하려고 남기는 섹션이므로, 이 세션에서 한 질문과 요청, 그에 대한 결정을 시간 순서대로 아래 형식으로 적는다.
  - 항목마다 `<번호>. <사용자의 질문이나 요청> > <결정>` 한 줄로 쓴다. 질문과 요청은 사용자가 쓴 말을 그대로 옮기고, 너무 길면 뜻을 바꾸지 않는 범위에서 줄인다. 구분자 `>`는 이스케이프하지 않는다.
  - 결정에는 무엇을 하기로 했는지 쓰고, 근거가 있으면 짧게 덧붙인다. 답하면서 추천했지만 사용자가 아직 고르지 않은 것은 그 항목의 결정 칸 안에 `추천`으로 표시해 결정과 구분한다.
  - 결정이나 선택으로 이어진 사용자의 질문과 요청만 항목이 된다. 항목이 하나도 없으면 섹션을 만들지 않는다. 푸시 전 리뷰나 리뷰 봇의 지적, 커밋 해시, 도구 호출 같은 진행 과정은 적지 않는다.
  - 페이지에 이미 `## 결정내역`이 있으면 새 섹션을 만들지 않고 이어지는 번호로 뒤에 덧붙인다.

  ```markdown
  ## 결정내역
  1. 노션 스킬에서 페이지 읽기 섹션 제거해도 되는지 검토해줘 > 제거해도 됨. 같은 내용이 MCP 도구 설명에 있음. 다른 섹션의 겹치는 내용도 같이 정리하자고 추천.
  2. 추천대로 같이 정리해줘 > 진행.
  ```

### 3. 댓글 정정

이미 단 Notion 댓글의 내용이 바뀌면 기존 댓글을 지우지 않고 취소선으로 남긴 뒤, 같은 스레드에 정정 답글을 단다.

- 기존 댓글 수정에 쓰는 `notion-update-comment`는 Business 플랜이 필요하다. 플랜이 없으면 `entitlement_required`로 실패한다(2026-10-28 실측). 이 오류가 나면 재시도하지 않는다.
- 취소선을 긋지 못했으면 사용자에게 Notion에서 기존 댓글을 직접 편집해 취소선을 그어 달라고 안내하고, 댓글 링크를 함께 준다.
- 정정 답글은 `notion-create-comment`에 `page_id`와 기존 댓글의 `discussion_id`를 넣어 같은 스레드에 단다. 첫 줄은 `위 댓글을 정정합니다.`로 시작한다. 취소선이 그어지지 않은 채 정정 답글만 달려도 읽는 사람이 어느 댓글이 바뀌었는지 알 수 있게 하려는 것이다.
- 게시 전에 정정 답글 전문을 출력하고 승인받는다. 상위 스킬이 취소선 범위와 정정 전문을 모두 출력하고 승인받았으면 다시 하지 않는다.

### 4. 연결과 접근 실패

Notion 작업을 시작할 때 첫 도구 호출 전에 `ToolSearch`로 `select:mcp__notion__notion-fetch,mcp__notion__authenticate,mcp__notion__complete_authentication`을 조회해 연결 상태를 판정한다. 조회는 있는 도구만 돌려준다. 작업 도중 도구 호출이 인증 오류(401, 토큰 만료)로 실패하면 `notion-fetch`가 남아 있어도 인증이 끊긴 것으로 보고, `authenticate`가 있으면 아래 재연결 순서를, 없으면 `/mcp` 안내를 따른다. 재연결 순서는 한 작업 요청 안에서 한 번만 수행한다.

- `notion-fetch`가 있으면 연결된 상태다. 원래 작업을 진행한다.
- `notion-fetch`가 없고 `authenticate`가 있으면 인증이 끊긴 상태다. 사용자에게 `/mcp` 입력을 먼저 요청하지 않고 아래 순서로 재연결한다.
- `notion-fetch`와 `authenticate`가 모두 없으면 서버가 연결되지 않은 상태다. 사용자에게 알리고 `/mcp`에서 `notion` 서버 상태를 확인하도록 안내한다.

재연결 순서는 다음과 같다.

1. `mcp__notion__authenticate`를 호출해 인증 URL을 받는다.
2. macOS면 `open "<URL>"`로 기본 브라우저에서 연다. 그 밖의 환경에서는 열지 않는다. 어느 경우든 URL을 응답에 함께 적는다.
3. 사용자에게 브라우저에서 승인한 뒤 알려 달라고 하고 응답을 기다린다. 승인을 대신할 방법은 없다.
4. 사용자가 승인했다고 하면 위 조회를 다시 한다. `notion-fetch`가 있으면 원래 작업을 이어 간다.
5. 여전히 `notion-fetch`가 없으면 승인 뒤 브라우저 주소창에 남은 `http://localhost:<port>/callback?code=...&state=...` 전체 URL을 달라고 해서 `mcp__notion__complete_authentication`의 `callback_url`로 넘기고, 4단계의 조회를 한 번 더 한다. `notion-fetch`가 있으면 원래 작업을 이어 간다.
6. 그래도 `notion-fetch`가 없거나, 사용자가 승인을 거부했거나 콜백 URL을 주지 못했거나, `authenticate`가 URL을 주지 않았거나, 도구 호출이 오류를 돌려주면 받은 오류(없으면 도구가 여전히 없다는 사실)를 그대로 보여주고 `/mcp`에서 `notion`을 직접 재인증하도록 안내한다. 같은 절차를 자동으로 반복하지 않는다.

인증은 되어 있는데 조회나 수정이 권한 문제로 실패하면 사용자에게 Notion URL 확인과 공유 설정(연동 계정 접근 허용)을 안내한다.
