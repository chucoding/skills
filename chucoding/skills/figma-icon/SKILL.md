# Figma 아이콘 반영 절차

Figma 시안을 화면 코드로 옮길 때 아이콘이 시안과 다르게 들어가는 일을 막는 절차다. Figma MCP로 asset을 받는 것만으로는 부족하다. 저장소에 이미 있는 파일을 대조 없이 다시 쓰거나 상태별 variant를 빠뜨리면 같은 결과가 난다(근거는 `6. 근거 사례`).

`figma:figma-design-to-code` 스킬을 대신하지 않는다. 그 스킬대로 시안을 읽으면서 아이콘 부분에 이 절차를 더한다.

## 1. asset SVG를 받아 쓴다

- 시안의 아이콘은 그 노드의 asset SVG를 받아 쓴다. 스크린샷을 보고 path를 그리거나 비슷한 아이콘 라이브러리 것으로 바꾸지 않는다.
- 받는 방법과 주의점은 `4. 받는 방법과 주의점`을 따른다.

## 2. 기존 아이콘도 대조한다

저장소에 같은 이름이나 같은 용도의 아이콘 파일이 이미 있어도 **파일이 있다는 것만으로 다시 쓰지 않는다.**

1. 시안 노드의 asset SVG를 받는다.
2. 저장소 파일과 아래 값을 대조한다.
   - 크기와 viewBox
   - 도형 구성(path, rect, circle의 개수와 모양)
   - 도형마다 `fill`, `stroke`, `stroke-width` 값. `currentColor`로 바뀐 곳이 있으면 어떤 원본 색을 대신하는지 확인한다.
3. 하나라도 다르면 Figma 것으로 바꾼다. 저장소 파일이 다른 배경(예: 밝은 사이드바)에 맞춰 손본 파일일 수 있으므로, 같은 원본에서 왔다는 이유로 같다고 보지 않는다.
4. 저장소 파일의 주석이나 TSDoc에 적용 조건(예: "밝은 배경에서만 성립")이 있으면 지금 화면이 그 조건을 만족하는지 확인한다. 만족하지 않으면 다른 것으로 본다.

## 3. 상태별 variant를 모두 받는다

- 시안의 아이콘 컴포넌트에 default, selected, hover, disabled 같은 variant가 있으면 화면에서 쓰는 상태를 모두 받는다.
- 각 variant의 SVG를 서로 대조해, 색만 바뀌는지 본체와 디테일의 색 역할이 바뀌는지 확인한다.
  - 한 가지 색만 바뀌면 `currentColor` 한 벌로 처리할 수 있다.
  - 색이 SVG 안에 고정된 2톤 아이콘이거나 본체와 디테일 색이 서로 뒤바뀌면 `currentColor` 한 벌로 처리하지 않는다. 상태별 파일을 둔다.
- 허브(hd-cloud-client) 다크 사이드바 아이콘은 `src/widgets/Sidebar/ui/SidenavIcon.tsx`의 `{ default, selected }` 2벌 레지스트리에 `NavNode.iconMenu` 키로 등록한다. Figma 컴포넌트 이름은 `icon_sidenav_cloud`다. 사이드바 아이콘을 따로 만들기 전에 이 레지스트리부터 확인한다.
- 일부 상태를 지금 작업 범위 밖으로 미루려면 미루기 전에 `AskUserQuestion`으로 사용자에게 묻는다. 묻지 않고 "후속 티켓 범위"로 판단해 넘기지 않는다.

## 4. 받는 방법과 주의점

아래는 2026-11-23에 Figma MCP로 실측한 내용이다(파일 `OcDtaOoBVhTs3R8AQ78zht`). 실측하지 않은 동작은 `확인하지 않은 것`에 따로 둔다.

### `get_design_context`의 asset URL

- 응답에 아이콘마다 asset URL(`https://www.figma.com/api/mcp/asset/<id>.svg` 형식)이 온다. `curl -fL <URL> -o <파일>`로 SVG를 받을 수 있다.
- URL은 수명이 짧다. 응답을 받은 직후에 내려받는다. 시간이 지나 실패하면 `get_design_context`를 다시 호출한다.
- URL은 비밀처럼 다룬다. 커밋 메시지, PR 본문, 코드 주석, 문서에 붙이지 않는다. 출처를 남길 때는 Figma 노드 링크나 노드 id를 쓴다.
- 단순한 도형으로 된 아이콘은 SVG가 아니라 div로 올 수 있다. HDIT-5721에서 급여관리 아이콘이 15x12 회색 둥근 사각형과 흰 6x4 사각형, div 2개로 왔다. 이때는 응답에 있는 크기, 위치, 모서리 반경, 색 값으로 SVG를 직접 쓰고, 원본 노드 id를 SVG 파일이나 등록 코드 주석에 남긴다.

### `download_assets`로 노드 내보내기

- `defaultFormat: "svg"`를 주면 노드를 SVG로 내보낸다.
- **인스턴스 노드**를 내보내면 상위 프레임의 배경 rect와 큰 좌표 오프셋이 섞여 나온다. 아이콘 도형은 안쪽 그룹(예: `<g id="icon_sidenav_ERP">`)에 들어 있다. 그대로 저장하지 않는다. 아이콘 그룹의 도형만 남기고 viewBox를 아이콘 크기에 맞춰 다시 잡는다.
- `svgAssets`에는 숨은 variant 조각까지 섞여 온다. 서브트리에 아이콘이 20개를 넘으면 잘리고 `svgAssetsTruncated: true`가 붙는다. 화면 전체가 아니라 아이콘 하나만 담은 작은 노드를 지정한다.
- `nodeId`는 `^\d+[:-]\d+$` 형식만 받는다. `I…;…` 형식의 인스턴스 내부 id는 넣을 수 없다. 이때는 `get_design_context`의 asset URL을 쓰거나, 인스턴스 노드를 내보낸 뒤 위처럼 래퍼를 걷어낸다.

### 확인하지 않은 것

- 메인 컴포넌트 노드를 `download_assets`로 내보내면 래퍼 없이 깨끗하게 나오는지는 시험하지 않았다. 쓰려면 먼저 한 번 내보내 결과를 확인하고, 확인하면 이 절을 실측 사실로 고친다.

## 5. 작업 보고에 대조 결과를 남긴다

아이콘을 다룬 작업은 보고에 아래 표를 넣는다. 검증 기간에 이 스킬이 효과가 있었는지 보려는 것이다.

```markdown
**아이콘 대조**
| 아이콘 | Figma 노드 | 저장소 파일 | 상태 | 결과 | 바꾼 것 |
|------|------|------|------|------|------|
| <아이콘 이름> | <노드 id> | <파일 이름> | default | 다름 | <바꾼 값, 예: 흰 stroke 제거> |
| <아이콘 이름> | <노드 id> | <파일 이름> | selected | 새로 받음 | <받은 값> |
| <아이콘 이름> | <노드 id> | <파일 이름> | default | 같음 | 없음 |
```

- `결과`는 `같음`, `다름`, `새로 받음` 중 하나다.
- 사용자에게 물어 미룬 상태가 있으면 표 아래에 `미룬 상태`로 적고 사용자 결정을 함께 적는다.

## 6. 근거 사례

- HDIT-5721(급여/연말정산 사이드바, PR #3062, squash `90f1c24ea`)에서 1depth 아이콘 5개가 현행과 다르게 들어갔다. PM이 HDIT-4467 댓글(https://rsquare.atlassian.net/browse/HDIT-4467?focusedCommentId=150854)로 지적했다. 2026-11-23에 세션 기록을 분석한 결과는 아래와 같다.
  - `get_design_context`(노드 20932:75364) 응답에 5개 아이콘의 asset이 모두 있었다. 스크린샷을 보고 그린 것은 아니었다.
  - 저장소 `src/entities/payroll/ui/payroll-icon/`에 파일이 있는지만 확인하고 급여관리, 급여조회, 연말정산, 설정 4개를 그대로 썼다. Figma asset과 모양을 대조하지 않았다. 저장소에 없던 퇴직정산만 asset을 받아 저장했다.
  - 기존 4개는 HDIT-2784(2026-09-11, `59438957f`)가 레거시 ERP 아이콘을 **밝은 사이드바용**으로 손본 파일이었다. 본체를 `currentColor`로 바꾸고 급여관리와 급여조회의 디테일에 흰 stroke를 둘렀다. 사이드바는 3일 뒤 HDIT-2303(2026-09-14, `6b80e3761`)에서 다크로 바뀌어, 다크 배경에서 흰 외곽선 모양으로 깨져 보였다. `payroll-icon/index.tsx` TSDoc에 "허브 사이드바는 아직 밝은 배경이라…"와 다크 전환 시 `SidenavIcon` 레지스트리로 옮기라는 안내가 있었지만 반영하지 않았다. → `2. 기존 아이콘도 대조한다`
  - selected variant(본체 흰색, 디테일 `#907AF4`)도 받아 봤지만 "HDIT-2303 후속이라 범위 밖"으로 미뤘고 사용자에게 묻지 않았다. `currentColor` 한 벌뿐이라 선택되면 흰 디테일이 흰 본체에 묻힌다. 다크 2벌 레지스트리 `SidenavIcon`이 이미 있었지만 쓰지 않았다. → `3. 상태별 variant를 모두 받는다`

## 7. 검증 중

이 스킬은 2026-11-24부터 개인 스킬로 시험 중이다. Figma 아이콘을 다루는 작업에 몇 번 써 보고 `5. 작업 보고에 대조 결과를 남긴다`의 표로 효과를 확인한다. 효과가 확인되면 팀 위키 `homedot-hub/skills/homedot-design-skill`로 옮길지 사용자가 정한다. 그 전에는 위키 스킬을 고치지 않는다.
